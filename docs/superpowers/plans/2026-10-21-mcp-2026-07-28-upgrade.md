# MCP 2026-07-28 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve every client (claude.ai, Claude Desktop, Claude Code, MCP Inspector, the `fastmail` CLI, OpenClaw, Code Mode) from one SDK v2 server on `/mcp` that fully uses MCP 2026-07-28: stateless transport, form and URL elicitation, cache hints, complete tool annotations, and MCP Apps UI.

**Architecture:** `/mcp` moves from "v1 `McpAgent` Durable Object for 2025 clients + v2 stateless handler for 2026 clients" to a single `createMcpHandler(..., { legacy: "stateless" })` whose factory builds one v2 `McpServer` per request for both protocol eras. Features that need client support (elicitation, MCP Apps) are capability-gated and degrade to today's behavior. `/mcp/code` stays on its v1 stateless transport. The `FastmailMCP` Durable Object is retired in a final, separate deploy after a soak period.

**Tech Stack:** Cloudflare Workers, Hono, `@modelcontextprotocol/server` 2.3.1, `@modelcontextprotocol/client` 2.3.1, `agents` 0.28.1, `@modelcontextprotocol/sdk` 1.32.1 (Code Mode only), zod 4, Vitest (node environment).

**Spec:** MCP 2026-07-28 ([changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog), [elicitation](https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation)), MCP Apps 2026-01-26 ([spec](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx)), plus the Decisions and Client Matrix sections below, which record what was agreed for this repo.

## Decisions (agreed 2026-10-21)

1. **Unify on SDK v2.** The DO path no longer elicits anything, so its reason to exist (issue #42) is gone. One factory serves both eras through the agents stateless legacy lane. The DO is removed in Task 8, after a 7-day soak.
2. **MCP Apps:** a send review card on the four send tools, plus an email reader on `get_email`/`get_thread`. Approval never happens inside the app: its button opens the Access-authenticated `/approve/send/:id` page via `ui/open-link`.
3. **Form elicitation:** only `bulk_delete` and `bulk_move` with 25 or more emails. Clients without form support proceed as today, gated by annotations.
4. **CLI:** move to `@modelcontextprotocol/client` 2.3.1 with `versionNegotiation: { mode: "auto" }`. Elicitation is declared only on an interactive TTY.
5. **Out of scope:**
   - Tasks extension (absent from server 2.3.1).
   - `subscriptions/listen` notifications (tool lists never change at runtime).
   - `x-mcp-header`.
   - Sampling, roots and logging (unused, deprecated).
   - `allowedOriginHostnames` (would block MCP Inspector's browser origin).
6. **No new runtime dependency.** MCP Apps constants and the postMessage bridge are local code. `@modelcontextprotocol/ext-apps` is not added, which keeps the four-package pin set untouched.

## Global Constraints

- Keep exact pins: `agents` 0.28.1, `@modelcontextprotocol/sdk` 1.32.1, `@modelcontextprotocol/client` 2.3.1, `@modelcontextprotocol/server` 2.3.1. Add no runtime dependencies.
- Every registered tool must have an entry in both `TOOL_CATEGORIES` (`src/permissions.ts`) and `TOOL_ANNOTATIONS` (`src/tool-annotations.ts`, Task 2).
- Every tool input goes through `strictShape`. Unknown parameters stay a loud error.
- 2026-era results keep SDK-emitted `resultType`, `ttlMs` and `cacheScope`. Claude Code before 2.1.302 fails `tools/list` without them.
- Nothing except the authenticated `/approve/send/:id` page may approve a send. MCP Apps views and models can only open that link.
- Any tool returning email content is in `EXTERNAL_DATA_TOOLS` (`src/prompt-guard.ts`) so its text content is datamarked.
- Deploy with `env -u CLOUDFLARE_API_TOKEN npx wrangler deploy` from a clean, pushed `main`. Publish npm only by pushing a signed `v*` tag.
- No emails, domains, account IDs or team names in tracked files. `wrangler.jsonc` stays gitignored. Edit `wrangler.jsonc.example` and tell the user what to mirror locally.
- The repo is public. Never commit `WORKLOG.md`.

## Review Focus

1. **A claude.ai connector with a live 2025 session at deploy time** keeps sending its old `Mcp-Session-Id`. The next call must still succeed, or at worst return a 404 the client recovers from. Pinned by `legacy tools/list with a stale Mcp-Session-Id still succeeds` (Task 1).
2. **Hosts that ignore `visibility: ["app"]`** (Claude Code, the CLI, Code Mode) list the `ui_*` tools, so a model can call them. Results must be permission-checked, scoped to the owner and datamarked. Pinned in Tasks 5 and 6.
3. **Hostile email HTML** (scripts, remote images, tracking pixels) in the reader must render without scripts or network fetches. Pinned by `reader preview strips scripts and blocks remote images` (Task 6).
4. **A replayed or cross-user bulk `requestState`** must be rejected, not executed. Pinned by `bulk state minted for another user is rejected` (Task 3).
5. **The non-TTY CLI under OpenClaw** must never block waiting on a prompt. Pinned by `non-interactive client declares no elicitation capability` (Task 7).
